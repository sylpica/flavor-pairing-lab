# 根拠方針（Evidence Policy）

## 根拠区分
- **Measured（実測）**: 対象試料で直接測定・観測された情報。試料・条件・出典を伴う。
- **General（一般的知見）**: 文献で確立または報告された一般的な科学的知見。個別品種・商品の実測ではない。
- **Inferred（推測）**: 既知のデータから導いた探索的な推測。内部データと表示の両方で推測として保持し、実測のように断定しない。ホイールでは破線＋文字で区別する（色のみで区別しない）。
- **Insufficient（情報不足）**: 判断に必要な証拠が不足。未報告は「存在しない」ではない。

## 区別する原則
1. 化合物そのものの香り／特定食品からの検出／食品中の濃度／食品香味への寄与／官能評価で確認された特徴／組み合わせ時の知覚変化／一般機構からの予想、を混同しない。
2. GC-MS の検出だけで香味寄与が証明されたとは判断しない。寄与の主張には GC-O・AEDA・OAV・再構成・欠落試験・官能評価等の根拠を要し、リンク種別 `contribution` でのみ主張する。
3. 精油の成分比を食品全体の成分比として扱わない。
4. 異性体・同義語を混同しない。同名でも植物種が異なる場合は学名で区別する。

## 数値化の原則
- 香味の強さは定性区分（弱い／中程度／強い／データ不足）のみ。根拠のない100点満点の相性スコア・確率・濃度は作らない。
- 定量データを表示する場合は、数値・単位・測定条件・出典をセットにする。

## 情報源の格付け
- 成分濃度・相互作用の実測は査読付き原著論文を優先する。
- メーカー情報は商品・加工・原材料の確認に用い、化学的実測値の単独根拠にしない。
- 一般記事は実測値の根拠にしない。複数言語の転載を独立した研究として数えない。

## 不明の扱い
調査しても確認できない項目は内部データに「未確認」として残す。通常画面では根拠のある内容を中心に表示し、研究上重要な不足は明示する。文献がない項目は、空白の「不明」で放置せず、項目自体を設けない選択も含めて設計する。

## 足し算による合成
直接のデータが薄い対象では、関連エンティティ（交配親・祖先・近縁素材）のノート集合の足し算によるプロファイル合成も用いる。扱いは以下による。
1. 結果は Inferred（推測）区分とし、強度は弱い（weak）を上限とする。
2. 根拠文（scopeNote 等、利用者が読める場所）に、足し算による合成である旨を記す。
3. 化合物リンク（特に contribution）の根拠には使わない。ペアリングの相性判断には使わない（本アプリに相性スコアは存在しない）。
4. 適用した箇所は監査記録に列挙する。

## 味わいホイールの具体名（中分類）の対応づけ
味わいホイールは3階層で表示する（第1階層＝味覚・口腔感覚、第2階層＝具体名、第3階層＝化合物）。第2階層の具体名は、香味ノート（香り）を味カテゴリへ対応づけた「表示構造」の情報であり、感覚データの追加・改変ではない。データ層では香りノートと感覚（SensationEntry）を分離したまま保持し、対応づけは専用データ（src/data/taste-note-map.ts）で根拠つきで管理する。作法は以下による。
1. 対応づけは主対応1つ方式：1つのノートは最大で1つの味カテゴリにのみ対応づける（第2階層の重みの二重計上を避ける）。
2. 対応の根拠は3種に分ける。(a) 呈味成分：代表食品・代表化合物群に実際の呈味物質（糖・有機酸・アルカロイド・アミノ酸・カプサイシノイド・メントール等）が含まれる場合。(b) 味覚―嗅覚相互作用：香りによる甘味増強など、原著で示された交差感覚の知見に基づく場合。(c) 推測：代表食品の支配的な味からの連想など、(a)(b) に届かない場合。(a)(b) は一般的知見（general）、(c) は推測（inferred）として扱う。
3. 表示上の区別：推測の対応による具体名、および感覚データに無い味を対応ノートから導出したセグメントは、破線・薄色・「推測」の文字表記で区別する（色のみで区別しない）。導出したセグメントの重みは対応ノートの最大の重みとし、感覚データのように見せない。
4. 感覚の強さ（SensationEntry の値）は対応づけのために創作・改変しない。感覚データにある味で対応ノートが無い場合は第1階層のみ表示し、具体名を創作しない。
5. 味への足がかりが任意になるノートは対応づけず、理由を対応づけデータと監査記録に残す。
6. 対応づけを化合物リンク（寄与・組成・検出）の根拠や、ペアリングの相性判断の根拠に使わない。
